# Development

## Toolchain

- Swift 6.3, macOS 26 SDK, arm64.
- A full Xcode installation is **not** required. The project builds and packages
  with CommandLineTools only.

## Commands

```bash
swift build                 # build everything
swift run GymPassTests      # run the test suite
swift run GymPassAgent --demo
swift run GymPassApp
./scripts/build-app.sh      # assemble + sign dist/GymPass.app
make test app run-demo      # shortcuts
```

## Tests

`swift test` cannot discover tests when only CommandLineTools is installed:
SwiftPM does not add the swift-testing framework search path and its discovery
step finds zero tests. GymPass therefore uses a small custom runner in
`Sources/GymPassTests`:

```bash
swift run GymPassTests
```

It prints `PASS`/`FAIL` per test and exits non-zero on failure. The suite covers
scheduling, redaction, PureGym decoding, pass JSON/manifest/zip, CMS signing and
tamper rejection, persistence and outbox behaviour, the full Wallet route
contract, installation links and the refresh engine.

The signing tests use a throwaway self-signed identity generated by
`scripts/generate-test-identity.sh` into `Tests/Fixtures/test-identity.p12`
(password `gympass-test`). It is test-only and is never trusted by Apple.

## Demo mode

`--demo` (or `GYMPASS_DEMO=1`) substitutes mock PureGym, mock APNs, an in-memory
secret store and a separate demo database. It must be enabled explicitly; it is
never turned on by configuration.

## PureGym validity probe

The relationship between refresh hints and real invalidation is unverified. To
probe it with your own account, watch the Activity screen while:

1. Refreshing manually twice in quick succession and comparing whether the code
   changes.
2. Opening the official PureGym app and then presenting the GymPass code.
3. Trying an older retained code.

Record findings in `docs/research.md` and adjust `RefreshPolicy` if needed.

## Packaging

`scripts/build-app.sh` builds release binaries, draws the app icon
(`scripts/build-icon.swift` + `iconutil`), assembles the bundle, embeds the
agent LaunchAgent plist, and signs nested-first. Ad-hoc signing uses the
`launchctl` LaunchAgent path; a Team-ID-signed build can move to `SMAppService`.

## Adding a Wallet route

Routes live in `Sources/GymPassCore/Server/WalletHTTPServer.swift` and delegate
to `WalletService`. Add tests in `Sources/GymPassTests/ServerTests.swift` for the
status code, headers, authorization and body before changing behaviour.
